# 项目定位

`ieta-znz-deploy` 是 IETA 产品族独立维护的第三方基础容器部署工程。

当多个业务应用都依赖数据库、缓存、对象存储、搜索引擎、文档服务或流处理平台时，本项目统一选择版本、定义网络、维护启停入口和约束接入方式，避免每个业务发布包重复携带或定义一套基础容器。

## 本项目拥有的职责

- 第三方容器镜像版本选择、固定和升级评估；
- Windows Docker Desktop、Ubuntu AMD64、Ubuntu ARM64 的镜像拉取脚本；
- 共享 Docker 网络 `ieta-znz-deploy`；
- 稳定的 Compose 服务名、容器端口和数据卷；
- 基础容器的启动、停止、状态和发布校验脚本；
- 应用到基础 capability 的声明清单；
- 公共基础容器的初始化入口和运维文档。

仓库只维护镜像引用，不存放镜像 tar。用户通过拉取脚本把固定版本镜像下载到本机 Docker。

## 业务应用拥有的职责

- 应用镜像、可执行程序和应用专属配置；
- 只包含应用自身服务的 Compose 文件；
- 业务数据库结构迁移和数据升级；
- 指向共享基础服务的环境变量；
- 应用自身的启动、停止、健康检查和回滚；
- 在发布前验证所声明的基础能力真实可用。

## 明确不属于本项目的内容

- 业务应用镜像和源码；
- 业务数据库表结构迁移；
- 应用专属 runner、connector、插件和模型文件；
- 应用发布版本和应用生命周期决策；
- 镜像 tar 或其他镜像二进制副本；
- 未经登记、仅供单个应用临时使用的第三方容器。

## 稳定契约

| 契约 | 当前值 |
| --- | --- |
| Compose 项目名 | `ieta-znz-deploy` |
| 外部网络 | `ieta-znz-deploy` |
| Compose 文件 | `docker-compose.ieta-znz-deploy.yml` |
| 应用能力清单 | `apps/<app-id>.env` |
| 能力服务映射 | `scripts/common/service-catalog.env` |
| 镜像总清单 | `image-list.txt` |

容器内连接使用 Compose 服务名；宿主机端口仅用于宿主机运行的应用和运维访问。

## 设计边界的价值

该边界减少端口冲突、重复数据存储、不一致版本和无人负责的第三方镜像升级。共享不意味着强行混用不兼容版本：例如 Elasticsearch 7 和 Elasticsearch 8 作为不同 capability 独立维护。新增版本必须在本项目中登记、验证和发布。
